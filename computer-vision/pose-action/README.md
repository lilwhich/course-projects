# 基于 YOLOv8-Pose 的人体行为识别（站立 / 坐下 / 行走 / 蹲下）

摄像头实时提取 17 个骨骼关键点 → 落盘为 CSV → 提取时序特征 → 分类器判定行为。
实时窗口和离线报告两条路都能出结果。

## 安装

**方式一：一键脚本（推荐，换电脑就用这个）**

双击 `⓪一键安装环境.bat`。它会自动定位本机 Python、创建 `.venv`、

最后跑一次导入检查。需要联网，下载约 500 MB。

装完双击 `环境自检.bat` 确认状态，再按 ①→②→③ 的顺序用。

**方式二：手动**

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-lock.txt
```

`requirements-lock.txt` 是精确版本锁定（pip freeze 结果），

## 三步走

**1. 采集** —— 每类至少 4 段，每段 15~30 秒；蹲下 3 段即可

```bash
python recorder.py
```

| 键 | 作用 |
|---|---|
| `1` / `2` / `3` / `4` | 切标签：站立 / 坐下 / 行走 / 蹲下 |
| `空格` | 开始 / 结束一段录制（每段一个 CSV） |
| `s` | 截图存档 |
| `q` | 退出 |

采集要点（直接决定准确率）：

- **摄像头必须拍到膝盖以下**。笔记本摆桌上只拍上半身时，髋和膝都看不见，
  程序会提示"腿部关键点不足"——只露上半身时，站着和坐着在骨骼上无法区分。
  把笔记本放远、镜头抬高，或换外接摄像头，人退到 1.5~3 m。
- **同一个人、三套距离**：站 1.5 m、站 3 m 各录几段，否则模型学到的是"画面位置"而不是"姿态"。
- **坐下要真的坐下**：从站立到坐着的过程也录进去，过渡段信息量最大。
- **走路要横向走**：正面朝镜头原地踏步，和"站立"在骨骼上几乎没区别，必须真的左右走。
- **蹲下要从站立蹲到底再站起**：与坐下的区别是胯低于膝；坐着时胯与膝大致齐平。
- 背景别太糊，人别小于画面高度的 1/3，否则关键点抖动会盖过姿态差异。

**2. 训练**

```bash
python train.py
```

打印每折准确率、分类报告、混淆矩阵（存 `reports/confusion_*.png`），
并保存 `models/pose_rf.pkl` / `pose_mlp.pkl` / `pose_best.pkl`，元数据写入 `models/meta.json`。

> 交叉验证按**录制段**分组。同一段的相邻窗口高度相似，随机切分会把准确率抬高十几个点。

**3. 用起来**

```bash
python realtime.py     # 摄像头实时判定
python report.py --all # 全部片段离线分析，出三联图
```

## 四类怎么区分

| 行为 | 主要判据 |
|---|---|
| 站立 | 膝角约 175°，躯干接近竖直，髋中心位移很小 |
| 坐下 | 膝角降到约 100°，髋部下沉，身体横向展开 |
| 行走 | 髋中心持续位移，踝与腕出现过零率高的周期摆动 |
| 蹲下 | 膝角快速下降且**胯低于膝**，髋高比骤降，位移接近零 |

蹲下与坐下在单帧上接近，靠 `knee_above_hip`（胯相对膝的高度）这一特征分开。

## 特征怎么设计

原始坐标受人站多远、站偏左右影响，直接喂分类器会过拟合拍摄条件。
所以先做**平移 + 尺度归一化**：以两髋中点为原点、肩髋距为单位长度。

逐帧共 15 维，其中区分能力最强的几项：

| 特征 | 物理含义 | 主要区分 |
|---|---|---|
| `torso_angle` | 躯干与竖直方向夹角 | 坐姿前倾 |
| `knee_angle_L/R` | 髋-膝-踝夹角 | 坐 vs 站（175° → 100°） |
| `hip_angle_L/R` | 肩-髋-膝夹角 | 坐姿折叠 |
| `hip_height_ratio` | 髋高 / 框高 | 坐下时髋部下沉 |
| `bbox_aspect` | 框宽 / 高 | 坐下身体横向展开 |
| `ankle_spread` | 两踝水平距离 | 迈步 vs 并腿 |
| `speed` | 髋中心帧间速度（框高/秒） | 走 vs 站 |
| `knee_above_hip` | 胯相对膝的高度差 | 蹲 vs 坐 |

其余为 `torso_len`（远近代理量）、`wrist_below_hip`、`head_hip_dy`、`center_x/y`（轨迹与位移）。

窗口（默认 1.5 秒，步长 0.3 秒）上再取 **mean / std / min / max / 首尾差**，
加上归一化坐标的 **标准差**与**过零率**——走路的本质是周期性，
这两项是"走 vs 站"的主要判据。最终向量 **143 维**（15×5 + 34 + 34）。

## 窗口为什么按"秒"而不是"帧"

帧率不固定：同一份代码在 4 核 CPU 上约 11~13 FPS，在带显卡的机器上能到 60 FPS。
如果窗口写死"30 帧"，同一段 1.5 秒的行为在一台机器上是 30 帧、另一台上是 90 帧，
特征分布完全不同，模型换台电脑就失效。

所以窗口统一用时间：`WINDOW_SEC = 1.5`（≈2.4 个步态周期），滑窗步长 0.3 秒。
代价是每个窗口帧数不定，但窗口特征是统计量（均值/方差/过零率），与帧数无关。

## 性能实测（4 核 CPU，无独显）

| 设置 | 耗时 | 帧率 |
|---|---|---|
| imgsz=640，torch 默认 2 线程 | 613 ms | 1.6 FPS |
| imgsz=640，4 线程 | 135 ms | 7.4 FPS |
| **imgsz=480，4 线程（默认）** | **89 ms** | **11~13 FPS** |
| imgsz=320，4 线程 | 52 ms | 18 FPS |

关键一条是 `torch.set_num_threads(os.cpu_count())`——ultralytics 默认 2 线程，
在这台机器上白白浪费了 4 倍性能。已在 `recorder.py` / `realtime.py` 里设好。

## 常见问题

**摄像头打不开**：别的程序占用了，或者 `--camera 1` 试试外接摄像头。
**提示"腿部关键点不足"**：人站得太近或坐着，镜头只拍到上半身。后退到能看见膝盖。
**模型下载慢**：按上文「权重与数据」手动放置 `yolov8n-pose.pt`。
**准确率 99% 但实际用不了**：多半是采集时每类只在同一位置录，换距离就崩。
看 `confusion_*.png` 和 `meta.json` 里的 `per_class_recordings`。
**想更快**：`config.py` 里把 `IMGSZ` 降到 320。
**想更准**：换 `yolov8s-pose.pt`，或把 `WINDOW_SEC` 调到 2.0（覆盖两个完整步态周期）。

## 已知局限

- **只在合成数据上验证过**。仓库不含真实采集数据，`make_demo_data.py` 生成的是理想姿态，
  在其上 RandomForest 交叉验证 1.00、MLP 0.986；这两个数字不代表真实表现。
  真实数据因遮挡、光照、服装，通常落在 85%~95%（预期值，本仓库尚无实测）。
- **蹲下样本偏少**。合成数据里 squat 仅 3 段，其余三类各 6 段，类别不平衡。
- **只支持单人**。画面多人时只取框最大的那个人。
- **必须全身入镜**。只拍上半身时站与坐无法区分，这是物理限制，调参解决不了。
- `reports/doc/` 下的配图由 `gen_doc_figs.py` 生成，示意数据来自合成数据，非真实采集。
